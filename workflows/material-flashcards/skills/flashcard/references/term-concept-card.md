# 概念学习卡

当用户要求术语卡、概念卡、小白解释、费曼学习法解释，或要求把概念结合本次材料的实际使用来制作卡片时，使用本 reference。

## 目标

概念学习卡不是百科摘要，也不是把每个 Q&A 都做成卡。它只保留能长期复用的概念缺口：先解释为什么要懂，再讲清概念本身，最后落到本次材料、流程、表格、代码或场景里怎么用。

全程使用费曼学习法：假设读者没有背景知识，用普通语言、生活类比、最小故事或反例解释；不要用术语套术语。

## 判定顺序

概念学习卡只分三类，按下面顺序判定，保证 MECE：

1. 主要卡点是混淆两个概念时，做区分型概念卡。
2. 主要卡点是流程、机制、规则、参与方或输入输出时，做运作型概念卡。
3. 其他单个概念，做定义型概念卡。

不要为场景应对、选择判断、情绪观点或临时个案单独造卡；只有它们能沉淀成稳定概念时才制卡。

## 模板

### 定义型概念卡

```markdown
## <术语/概念> 是什么

【Why｜为什么要懂它】：<它为什么会在本次材料里出现；不懂它会导致什么误解、误判或错误动作。>

【What｜它到底是什么】：<用人话解释概念本身；说明它不是哪个容易混淆的东西。>

【How｜怎么理解 / 怎么用】：<用费曼讲法拆机制或例子；最后落到本次材料里怎么判断、怎么表达、怎么操作。>
```

### 区分型概念卡

```markdown
## <A> 和 <B> 有什么区别

【Why｜为什么要区分】：<混淆后会导致什么错误判断或错误动作。>

【What｜核心差异是什么】：<分别用一句人话解释 A 和 B，再说最大差异。>

【How｜本次怎么判断】：<给判断规则：什么场景用 A，什么场景用 B。>
```

### 运作型概念卡

```markdown
## <机制/规则> 是怎么运作的

【Why｜为什么需要它】：<它解决什么规模、效率、风险、一致性、激励或协作问题。>

【What｜核心模型是什么】：<谁参与、输入是什么、输出是什么、核心规则是什么。>

【How｜它怎么跑起来】：<按 2 到 4 步讲流程；最后写本次材料里怎么识别、判断或应用。>
```

## 规则

- 一个概念缺口 = 一张完整卡；不要把 Why、What、How 拆成多张卡。
- `##` 正面必须直接暴露卡片问题：`是什么`、`有什么区别` 或 `是怎么运作的`。
- `【Why】` 写“为什么本次要懂它”，不是泛泛写重要性。
- `【What】` 写人话定义、核心差异或核心模型，不做百科摘要。
- `【How】` 必须落到本次材料的判断、表达、填写、选择、验证或避坑动作。
- 每个字段 1 到 3 句；如果一个字段里出现多个独立概念，另开一张完整概念学习卡。
- 卡片正文使用 `【字段】` 文本，不使用 Markdown `###`，避免 Decks 切断卡片。

## 完成标准

- 每张概念学习卡只属于定义型、区分型、运作型之一。
- 每张概念学习卡都有 `【Why】`、`【What】`、`【How】`。
- 每个字段都使用费曼讲法，读者没有背景知识也能读懂。
- 卡片数量等于 `##` 标题数量。
- 卡片正文里没有 H3 及以下 Markdown 标题。
