# 技术方案保留九个语义章节并允许按内容展开三级标题

ADR-0089 规定的九个二级标题继续作为正式技术方案稳定的语义锚点，顺序和含义不变。正文允许在
所属二级章节内按项目真实内容使用动态 `###` 标题，但禁止 `####` 和手工 `1.1` 式可见编号；不为
凑模板生成空标题。该决定只修订 ADR-0089 的扁平呈现限制，不改变其余决策。

八个分段 Skill 继续产出原有片段，但片段可以携带最终组装所需的 `###`。接口、数据与存储、状态
与并发、性能与容量、稳定性与观测、安全与合规、兼容与迁移等细节先做适用性判断，只展开与当前
项目有关的内容。主架构图仍为总体方案的强制产物；辅助图仅在文字和主架构图不足以说明关键闭环时
创建，必须可编辑并由正文明确引用。

背景、目标、调研和收益中的关键数字必须标明来源、时间、口径与证据状态，并区分现状事实/已测、
估算、目标和待确认。方案收益同时披露适用场景、不适用场景、方案代价与关键取舍。

本变更不修改 `technical-solution-design` 的十三个 Step 的 ID、名称、顺序或 executor，也不修改
Stage、Route、Condition、Output、三个人工门禁、Workflow YAML Schema、Thrift IDL、Runtime、
State、Storage 或公开 CLI 结构。五份生产 YAML 中只有 `prompt.yaml` 的写作与审校指令变化；
`workflow.yaml`、`condition.yaml`、`flow.yaml` 和 `loop.yaml` 保持不变，因此使用 `targeted` 验证档。

人工审核记录：2026-08-31，用户收到五 YAML 逐份影响说明、`workflow.yaml` 的零 Step diff、九个
二级语义章节与动态三级标题的前后示例，以及证据和适用性门禁后，明确回复“你全程推进”。
