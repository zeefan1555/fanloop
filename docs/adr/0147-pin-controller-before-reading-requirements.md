# Select the pinned controller before reading Requirement State

An initialized Requirement's actual `.fanloop/configuration-snapshot` is its configuration authority. An unrelated global current or caller author override cannot replace or prevent reading a valid pin. A missing legacy pin keeps the existing default-source behavior until explicit protection. Invalid managed pins fail without fallback.

Both the direct binary and npm launcher select `bound-release-home` before decoding State. They resolve an explicit Root using command scope and actual flag semantics. They never scan releases, infer a binary from creation provenance, migrate State, or replay history. A healthy legacy controller without a journal remains selectable, but that does not prove its external configuration is protected.

Controller selection verifies physical configuration resources and stored manifest identity without decoding Workflow YAML or validating Routes. It derives package names from the same complete file traversal; this identity is not a claim of Workflow validity. The selected exact controller owns Workflow loading and its original error/Doctor protocol. Protection fixes identity before its exact source controller performs health checks, then rechecks the same resources through copying and publication. Ordinary configuration reads, imports and publication retain complete semantic validation by their running CLI.

A Requirement launcher that rejects controller selection before starting a trusted CLI returns the public INTERNAL JSON envelope on stderr, leaves stdout empty, and uses the existing INTERNAL exit code. The private generated `commands.json` contains Cobra/CommandSpec metadata plus the complete empty-message error envelope and exit code produced by the existing Go output and error adapters. Node fills only the diagnostic message and parsed command, Root and dry-run metadata; it does not duplicate the error catalog or envelope schema, add details or expose environment values.

This narrowly amends ADR-0073 and ADR-0074 only at the launcher-before-CLI boundary: no CLI process ran, so this rejection creates no CLI execution-log entry. It must not execute the global binary, a rejected controller, the original business command or a hidden reporter to obtain a log. Node adds no logger or lock implementation. Once execution enters Go, successes and failures, including Go controller-selection failures, continue through the single `Execute` capture and best-effort log adapter. Rootless commands, installation and existing spawn-error behavior are unchanged. The main Agent explicitly approved this boundary on 2026-10-27; it does not claim that an unlogged Node preflight failure is a logged CLI invocation.

Every normal bound invocation uses the controller data home and four controller Skill roots, disables automatic updates, and internally injects the actual pin as `FANLOOP_CONFIG_SOURCE`. This partially amends ADR-0144's override prohibition. Caller overrides remain untrusted. Explicit `config rebind` alone retains the validated caller data home for installed-target selection while the controller interprets State. The next invocation rereads the actual pin, not historical controller current or journal intent.

The pinner keeps one absolute Root argument and prints only the exact controller binary path on success. `FANLOOP_PROTECT_BINARY` selects a physical candidate manager that supports `__protect`. `FANLOOP_CONTROLLER_RELEASE` selects the original physical Release whose binary performs status, requirement Doctor, and installation. These variables only select paths inside the script; they do not add a public DTO, flag, or persistent manager identity. A default current without protection support fails without scanning, fallback, or global installation. Prepared retries use the journal's intent, not a new source override.

New initialization protects the exact installed binary, both entrypoint Skills, and complete configuration before returning success. Immutable snapshots move without changing publication identity, bytes, or executable bits. Author initialization binds the controller but retains its original live pin and reports `author/live` on stderr. Explicit protection freezes the full current author resource tree, including dirty files and executable bits, into a non-managed capture. A capture does not gain synthetic Git or Fornax provenance.

`idl/storage.thrift` owns the independent schema-1 ControllerBinding journal. Its operation distinguishes initialize from protect. Prepared protect records exact source and target identities, previous pin existence, and the raw digest of State, Output, and Events. Health subprocesses run outside the Root lock. Source and copy bytes and modes are checked before and after copying and again before publication. Release and configuration resources reject symlinks, special files, and linked ancestors at this boundary. Only documented installation links are permitted outside the physical resource trees.

Both entrypoints enforce the journal's existing i32 schema contract before dispatch. Each top-level `schema_version` occurrence must be null or an integer token within i32 range; objects, arrays, strings, booleans, fractional and exponent spellings fail even when a later member is `1`. The final JSON-decoded value must still equal 1. Escaped top-level key names are decoded; strings and nested values do not masquerade as top-level fields. Repeated integers retain typed decoding behavior: `2,1` is accepted, `1,2` is not, and an out-of-range integer followed by `1` still fails. A preceding null followed by `1` remains accepted. Node retains its existing final-value policy, including refusing a final null. This adds no general duplicate-field policy, does not change other fields, and changes no journal field or Schema version.

Both journal timestamps use the exact grammar `YYYY-MM-DDTHH:mm:ss[.digits](Z|±HH:MM)`. Dates follow the proleptic Gregorian calendar, including year 0000. Time and offset hours are 00..23; minutes, seconds and offset minutes are 00..59. Fractions use a dot followed by one or more ASCII digits, without a length limit. Comma fractions, offset 24:00 or 00:60, lowercase separators, surrounding whitespace and final newlines are invalid. Prepared and committed times have no ordering constraint. The same raw string fixtures apply to both fields and both entrypoints; permissive library RFC3339 extensions do not expand this grammar.

Prepared protect can resume only its recorded transaction with unchanged resources and protected business bytes. Failure rolls back only a pin still equal to this transaction's written value, preserving the journal and identifiable staging. Unknown or drifted paths are never deleted or replaced. Prepared initialize always blocks, even if its initial State appears complete or the same request repeats. It never recreates State, supplements a committed marker, or guesses request identity. Initialization uses the Store's existing exclusive lock and private commitLocked, with no nested Commit or locked subprocess.

Freezing an author-live binding archives its exact committed journal before preparing the second transaction. The healthy Release is reused without replacement. Committed journals retain history but do not undo later rebinds or constrain subsequent business writes.

This partially amends ADR-0105 only for controller selection of bound Requirements. Unbound current-schema compatibility and all structural, State, Output, History, and Route checks remain. It partially amends ADR-0132 for identity-preserving local capture and ADR-0138 for successful initialization's complete binding. Rootless refresh behavior, default Git and HTTPS/SSH policy, distribution, and exec signal semantics remain. It does not restore retired maintainer workflows, Workflow digest gates, automatic migrations, or production YAML seeds.

Required field 18, `release_resources_sha256`, preserves resource identity across interrupted protection. ControllerBinding remains schema 1 because it has not been released. Missing field 18 fails without migration or guessed identity. No-journal legacy selection remains supported.

The resource digest uses the existing strict traversal, without a second scanner or durable file list. Its canonical bytes start with `fanloop-controller-release-resources-v1\n`, then the DirectoryDigest's 64 lowercase hex characters and LF. Each relative path, sorted by UTF-8 bytes with `/` separators, contributes its path, NUL, a type marker and LF. Directories, including `.` and empty directories, use `d`. Ordinary files use `f:` followed by three octal digits for their `0777` permissions. SHA256 of these bytes is the field-18 identity. Directory permissions, owner, mtime and absolute paths are excluded. Original DirectoryDigest behavior is unchanged.

Plan fixes this identity before health validation. Prepared retries, source checks, copied and published resources, committed dispatch, and archived or reused author controllers must match that same identity. Source retirement does not affect committed dispatch, which verifies only the local physical Release. This retains unchanged partial-copy recovery and rejects byte, permission, file-set and directory-set drift. The digest is not a signature against simultaneous malicious changes to the journal and resources.

The current managed-directory layout, its four links, unknown-entry rejection, activation locks, atomic exchange and retained rollback backups remain governed by `0147-migrate-managed-current-for-distribution-updates.md`.
