# 记录核心技术决策与取舍

读取第 1 至第 6 章、主架构图和
[What-Why-How 推导标准](../technical-solution-review/references/reasoning.md)。只记录会实质影响结果、成本、
边界或后续演进的核心决策，不把普通实现细节包装成决策。

每项决策必须包含：

1. 决策背景及对应的问题、目标和约束；
2. 至少两个真实可行选项和共同评价维度；
3. 最终选择及 Why；
4. 未选方案及未选原因；
5. 已接受的代价、适用边界、失败条件和触发重评条件。

一致性与性能、实时性与成本、短期交付与长期演进、平台化与定制化仅在真实存在冲突时展开。

## 产物列表

以下逻辑产物均写入 `.technical-solution/sections/07-decisions.md`：

| 逻辑产物 | 完整性要求 |
| --- | --- |
| 决策清单 | 每项可回溯到问题、约束、总体方案或关键模块。 |
| 备选比较 | 使用同一维度比较真实可行选项，不制造陪跑方案。 |
| 后果与边界 | 明确代价、风险、失败边界和重评条件。 |

片段不得出现 `#` 或 `##`；允许 `###`，禁止 `####` 和手工 `1.1` 编号。上游变化时只上报最早
受影响的 feedback Condition；否则上报 `technical_decisions_recorded` 和片段路径。
