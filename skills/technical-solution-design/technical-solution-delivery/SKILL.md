# 规划方案落地

读取已批准的 `01-background.md` 至 `07-benefits.md` 和架构图，把方案转为可执行计划：

1. 迁移计划：阶段、范围、依赖、数据处理、兼容边界、负责人和完成信号；
2. 发布验证：灰度顺序、观测指标、流量或数据核对、通过阈值和停止条件；
3. 风险回滚：风险、触发信号、止损动作、回滚步骤、数据恢复和责任人；
4. 后续演进：仅记录已知但不属于本次的演进项、触发条件和前置基础。

说明存量与增量如何切换、双写或回放如何校验、失败后如何恢复；不以“观察一段时间”“必要时
回滚”代替判定标准。计划必须与架构、容量、依赖和验证目标一致。

将结果写入并回读 `.technical-solution/sections/08-delivery.md`。片段不得出现 Markdown 标题，
使用阶段表、风险表和验收清单表达；不得引入未经批准的新架构方向。

发现上游结论需变更时只上报最早受影响的 feedback Condition；否则上报
`delivery_plan_defined` 和片段路径。
