# 记录结果与收益

开始前读取 [What–Why–How 推导标准](../technical-solution-review/references/reasoning.md)。收益判断须
说明具体机制如何影响目标及证据为何支持该判断，并交代验证结果或验证计划。

读取已批准的第 1 至第 8 章。逐项目标建立“基线—手段—验证—结果”
映射，并区分：

1. 已测效果：给出环境、样本、时间窗口、指标口径和结果；
2. 预期效果：给出测算依据、验证计划和达标阈值，不写成既成事实；
3. 业务价值：对用户体验、资金安全、业务规模、交付速度或成本的可验证影响；
4. 技术价值：性能、可用性、一致性、复杂度、维护成本和演进能力；
5. 适用边界：适用场景、不适用场景、前置条件、方案代价与关键取舍；
6. 复用价值：可复用边界和接入成本。

不用“显著提升”“大幅降低”等主观形容词替代数据。每项价值必须回扣目标和具体手段，无法量化
时写明验证方式和负责人。所有数字标明来源和证据状态，明确区分现状事实/已测、估算、目标与
待确认。

## 产物列表

以下逻辑产物均写入 `.technical-solution/sections/09-results.md`：

| 逻辑产物 | 完整性要求 |
| --- | --- |
| 目标与收益映射 | 每项目标对应具体手段、收益及适用边界，说明代价和取舍。 |
| 验证计划 | 预期效果有测算依据、验证方法、达标阈值及负责人，与目标口径一致。 |
| 已有结果及证据状态 | 稳定性、成本、耗时、资源、转化、研发效率、故障率或 SLA 等已测结果附来源、环境、样本、时间与口径；无实测结果时明确说明。 |
| 替代证据 | 无法量化时提供接入方数量、复用范围、线上事故变化或业务反馈等明确证据。 |

逐项回读产物内容，核对收益推导、验证覆盖及证据状态。片段不得出现 `#` 或 `##`；允许按
真实内容使用 `###`，但禁止 `####` 及手工 `1.1` 式标题。优先用效果表和价值映射表表达。

发现上游结论需变更时只上报最早受影响的 feedback Condition；否则仅在产物列表逐项完整时上报
`results_and_benefits_defined` 和片段路径。
