# 理解原始材料

先理解，再记忆。本 Step 只建立来源模型；不得因为一句话看起来适合问答就直接制卡。

## 理解方法

读取已确认目标和本地材料，记录：

- 材料结构、主题、论证或事件顺序；
- 可回到原位置的事实、原话或明确行为；
- 来源、作者/说话者归因、必要日期或版本；
- 例子、情境、关系、前置概念与限定条件；
- 矛盾、歧义、缺失因果和未知。

每条关键陈述只使用以下证据状态之一：

1. **来源事实**：材料明确表达或可直接观察；
2. **被归因的判断**：专家、咨询者或其他主体的观点，保留归因，不写成客观事实；
3. **用户理解**：用户自己的解释或复述，不能冒充来源原意；
4. **unknown**：材料与已确认输入均未支持。

情绪、动机、诊断和因果只有来源明确表达或用户明确确认时才能记录，并保留其证据状态。不得根据语气、行为或常识补造心理状态。可安全隔离的未知保留为 unknown；会使卡片失真或不可安全回答的未知使 Step `blocked`。

## 外部核对与隐私

**私密材料不得进入 Event / Trace / CLI 日志或未确认的群聊**。

私密原文不得发送给搜索、MCP、Web 或其他外部服务。外部概念核对只能使用已去除姓名、原句、唯一日期或金额、私密 URL 和其他再识别线索的问题，或使用目标文件中记录的明确范围授权；查询与答案仍只写权限受限本地文件。

完整材料、逐段理解、查询、详细错误和具体未知只保存在 Requirement Root 内权限受限、通用命名的理解文件。Summary 与 Evidence 只含相对路径、SHA-256、固定分类和最小非敏感摘要。

完成时上报 `source_understood`；需要改目标或已接受的来源理解时，只上报最早受影响的 `review_goal_changed` 或 `source_understanding_changed`。
