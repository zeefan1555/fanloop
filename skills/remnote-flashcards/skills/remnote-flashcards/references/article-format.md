# RemNote 普通文章格式

创建、修改或修复普通文章时使用本规范。文章仍写入每日笔记，但不制作闪卡。

## Rem 结构

- 文章根节点是一个 H3 Title Rem。
- Title 的 `remType` 保持 `text`，不设置为 Document，避免文章出现在侧边栏。
- Title 使用两个 Tag：一个 HOME 中最具体的主题 Tag，以及 `HOME / 03-RESOURCES / 文章` 类型 Tag。
- H4 主章节、H5 小标题、正文、列表和代码块都是 Title 的直接子 Rem，并按阅读顺序同级排列。
- 正文不缩进到 Header 下；Header 只负责显示层级。
- 全文不使用制卡语法，回读时确认没有 `cardDirection`。

结构示例：

```text
每日笔记
└─ 文章标题（H3、text、主题 Tag、文章 Tag）
   ├─ 结论（H4）
   ├─ 正文
   ├─ 问题与目标（H4）
   ├─ 正文
   ├─ 原理与方案（H4）
   ├─ 工作流程（H5）
   ├─ 正文
   └─ ASCII 图代码块
```

## 写作逻辑

按读者理解问题的顺序组织文章，不按时间线写流水账。默认从下面七段推理链中保留有信息的章节：

1. **结论**：先用 2–5 句回答最终理解或建议，并说明成立条件。
2. **问题与目标**：说明问题为什么值得写、哪里不清楚，以及本文要解决什么。
3. **判断逻辑与约束**：按“事实 → 约束 → 判断”展开，让读者能复现结论。
4. **原理与方案**：先给总览或示意图，再解释 2–3 个关键机制如何协作。
5. **关键决策与取舍**：比较真正可行的选择，说明选择理由和付出的代价。
6. **落地、踩坑与验证**：记录实际做法、遇到的问题、修复方式和可回读的证据。
7. **适用边界与下一步**：指出结论在哪些条件下不成立，以及接下来可以做什么。

短文章至少保留“结论、判断逻辑、原理或做法、验证或边界”。调研、关键决策、踩坑和下一步只在确有内容时增加。每章先说判断，再给原因或证据；架构、命令和代码用于解释判断，不单独堆材料。

## ASCII 示意图

ASCII 图必须放进一个 fenced `text` 代码块，使空格、换行和等宽排版保存在同一个 Rem 中。不要把图拆成多个 Rem。图外的 `→`、`>>`、`::` 等符号可能触发制卡语法，流程符号放进代码块。

````markdown
```text
调用方
  |
  v
remnote-cli -> MCP Server -> Automation Bridge -> RemNote
```
````

## 写入流程

1. 找到当天 Daily Document、最具体的主题 Tag ID 和“文章”Tag ID。
2. 用 `journal --no-timestamp --tag-ids <CATEGORY_REM_ID> <ARTICLE_TAG_ID>` 创建 H3 Title Rem。
3. 保持 Title 为 `text`，不要设置 Document。
4. 用 `insert-children <TITLE_ID>` 一次写入按顺序排列的 H4、H5、正文、列表和代码块；它们都直接属于 Title。
5. 回读 Title 及其子 Rem，确认层级、顺序和代码块内容。

## 完成核验

- Title 直接属于正确的 Daily Document，是 H3、`text` 类型且没有 `cardDirection`。
- Title 只有一个最具体的 HOME 主题 Tag，并额外带“文章”类型 Tag。
- H4、H5、正文、列表和代码块都直接属于 Title；正文没有成为 Header 的子节点。
- ASCII 图是一个完整的多行代码块 Rem。
- 文章没有被设置为 Document，因此不会作为独立文档出现在侧边栏。
