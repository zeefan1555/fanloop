# 复杂概念的 ELI5 网页

复杂概念先用可视化全貌帮助理解，再拆成用于长期复习的原子卡。网页负责建立模型，闪卡负责稳定提取；两者不能互相替代。

## 触发条件

用户明确要求 ELI5、图解或可分享网页，且满足下列任一条件时制作 ELI5 网页：

- 用户明确表示从零开始、看不懂，且希望用独立图解理解。
- 概念包含多个相互作用的角色、阶段、状态转换或因果链。
- 不借助流程图、状态图或逐步演示，很难讲清整体机制。
- 为让单张闪卡独立可懂，需要重复大量相同背景。

简单定义、单一事实或一个短计算不需要网页。

## 制作与发布

1. 先按 [费曼学习法制卡](feynman-card-method.md) 建立白话模型，补齐术语、机制和边界。
2. 调用 `eli5` 技能制作移动端优先的单页图解。页面至少包含一个日常类比、类比到真实概念的映射、一个具体例子和一个主要反例或风险。
3. 用户要求分享或持久链接时，按 `eli5` 技能要求通过 Sites 发布并取得 HTTPS 链接；否则交付本地页面，不等待外部部署。
4. 同一概念修改时复用并重新发布原 Site，不重复创建站点。

## 写回 RemNote

只有已发布为 HTTPS 页面时才写回一份网页链接，不制作“记住网址”的闪卡；本地页面只作为本次交付，不写入 RemNote。准备阶段将链接交给对应写入者：Wiki 助手仅维护 Wiki，主 Agent 在汇合后写卡片或主题；最后一次相关修改后统一验证：

1. 已有 Wiki 标准概念笔记时，在其中新增或更新普通子 Rem：`ELI5 图解：<HTTPS URL>`。
2. 没有 Wiki 概念笔记但有多卡主题 Rem 时，把链接作为该主题 Rem 的普通子 Rem，不添加 Tag，不使用制卡语法。
3. 只有单张卡且无需建立 Wiki 时，把链接放在最后一个实际保留段落的末尾，作为可选延伸材料，不为链接强行生成 R。

写入前先搜索同一标题或 URL，已有则更新，避免重复链接。回读确认链接位于真实内容中且可以点击。

## 边界

- 网页是理解入口，不是卡片答案。每张卡在不打开网页时仍须独立可懂。
- 网页可以展示完整流程；卡片仍遵循最小信息原则，一个卡片只测试一个目标。
- 网页中的类比必须映射回真实术语，并明确类比失效的位置。
- Subagent 评审卡片时不读取网页内容，避免把网页当作隐藏前置知识。
