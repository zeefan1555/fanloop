# Control RemNote

用 Computer Use 完成 RemNote 的最后一公里操作，不把界面当作内容 API。

## 边界

- 普通搜索、读取、创建、更新、移动和回读优先使用 `remnote-cli`；写入前运行 `remnote-cli status`。
- 只有用户明确要求电脑操作，或 CLI 缺少对应原生能力时才操作界面。常见场景是检查侧边栏或用户明确要求查看练习队列。Card Cluster 不走界面，也不用 `object-add-powerup` 补 `cc`。添加与否只由 `flashcards apply` 的 `cardCluster` 决定，规则在学习卡契约。写后由 remnote-verify 用 `object-has-powerup` 回读。
- 内容与业务规则由当前任务对应的 RemNote 技能决定；本技能只负责可靠地完成界面动作。
- 不直接读取或修改 RemNote 应用数据目录。不使用 AppleScript、坐标脚本或其他桌面自动化替代 Computer Use，除非用户明确要求。

## 工作流

1. **锁定目标**
   - 先用 CLI 找到唯一的 Rem ID、标题、父级和预期状态。
   - 若存在同名内容，必须用 Rem ID、页面 URL、祖先或可见上下文消歧后再操作。

2. **连接应用**
   - 首次调用只执行 `let app = await cua.getApp("RemNote");`。
   - 名称无法解析时，使用当前 Computer Use 工具公开的 `cua.getState()` 获取可用应用，再按返回标识连接；连接后的操作只使用工具返回文档明确公开的 API。

3. **观察当前状态**
   - 先读取 `app.getAXState()`；只有可访问性树缺少必要视觉信息时才读取截图或 `getAXStateAndScreenshot()`。
   - 确认当前窗口、页面标题、URL 中的 Rem ID 或可见祖先与目标一致。未确认时只导航，不编辑。

4. **执行最小动作**
   - 优先点击可访问性元素索引；输入使用 `setValue` 或 `paste`。只有目标没有可访问性元素时才依据最新截图使用坐标。
   - 快捷键从当前菜单或 RemNote 可见提示中确认，不猜测快捷键。
   - 每次动作后立即读取新的 `getAXState()`，按新状态重新取得元素索引；不复用旧索引。
   - 动作未生效时先重新观察，再换一种确定的方法。避免重复点击和全局撤销；全局撤销可能回滚先前的 CLI 写入。

5. **核验结果**
   - 界面必须清楚显示预期原生状态，例如复选框已勾选且正文有删除线、目标出现在预期侧边栏或练习队列。
   - CLI 能读取的结构同时回读，确认 Rem ID、标题、父级、类型和内容没有被意外改动。
   - 只有界面证据与 CLI 回读都满足当前任务的完成条件时才报告完成；CLI 无法表达的原生状态以最新界面观察为准。

## 恢复

- 用户在操作期间改变窗口或页面时，刷新应用状态并重新定位目标。
- 弹窗、菜单或浮层遮挡目标时，先读取其内容；只关闭与任务无关且不会丢失数据的界面。
- 无法唯一定位目标、界面动作存在数据丢失风险，或结果无法视觉确认时停止并报告具体阻塞。
