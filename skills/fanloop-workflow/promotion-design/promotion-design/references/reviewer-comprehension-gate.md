# 陌生评委理解门禁

本门禁检查的不是作者有没有写全，而是一个不了解该业务、场景和项目历史的评委，能否在规定时间
内建立正确认知、复述项目主线，并理解作者为什么值得晋升。逻辑正确但只有作者看得懂，仍然不能
通过。

## 冷读约束

执行门禁时建立一个独立冷读视角：

- 评委具备通用业务和技术判断力，但不知道内部系统、组织关系、缩写、历史事故和默认共识；
- 只能读取当前审核的 `require_points.md` 或 `方案.md`；
- 不得读取聊天记录、`.promotion/brainstorm.md`、外部资料，也不得用 Agent 已知上下文补全文档；
- 用户给出答辩或阅读时长时必须按该时长检查；未给出时，时间适配只能标记为“待验证”，不能
  声称完整通过。

## 三步冷读

### 第一步：开场定位

只读标题和开场摘要，必须能够回答：

1. 这是一个什么业务或技术项目？
2. 为什么现在必须做？
3. 最关键的问题是什么，为什么难？
4. 作者负责什么，团队和协作方负责什么？
5. 作者做出的核心判断或选择是什么？
6. 项目当前取得了什么结果，或准备如何验证？

缺少任一项，记录“背景缺口”或“贡献模糊”。不能要求评委继续读后文才能知道这是个什么项目。

### 第二步：陌生评委复述

只依据当前产物，用不含未解释内部术语的六句话复述：

1. 场景和价值；
2. 三个核心问题及后果；
3. 三个目标；
4. 业务特点怎样产生场景约束和选型标准；
5. 为什么选择当前手段，它具体怎样工作；
6. 作者贡献、效果证据和仍未闭合的规划。

任何一句需要猜测、借用外部背景或添加原文没有的因果，记录“陌生评委无法复述”。复述只是
Review 证据，不写进最终方案正文。

### 第三步：线性困惑扫描

从标题开始按真实阅读顺序扫描，记录第一个以及全部后续困惑点：

- 内部缩写、系统名、角色名、流程名第一次出现时没有用普通语言解释；
- 使用“它、这个、上述能力、链路”等指代，但前文没有唯一对象；
- 按时间顺序罗列“先做了、然后做了、后来又做了”，却没有先给问题结构和结论；
- 细节、模块和实现清单早于主判断出现，评委不知道为什么要记这些内容；
- 指标、比例或收益没有基线、口径、目标或业务含义；
- 项目结果、团队贡献和作者个人判断混在一起；
- 一节读完后说不出它回答了什么、为什么与晋升判断有关。

## 结构化表达检查

评委学习的是未知项目，正文必须按认知依赖组织，而不是按作者的经历时间线播放：

```text
先给结论和认知坐标
→ 再给背景、问题和目标结构
→ 再解释业务特点、约束和选型判断
→ 再展开手段、证据与细节
→ 最后回扣价值、个人贡献和规划
```

每一节都使用“本节结论 → 必要证据 → 关键细节”的顺序。一段只承担一个主判断；历史顺序只在
解释演进或决策转折确有必要时使用，不能成为整篇骨架。

## 时间适配检查

有明确时长时：

1. 按实际展示方式估算或试读全文；
2. 保留评委理解主线、关键取舍、个人贡献和效果证据所需时间；
3. 删除不能改变评委判断的过程细节，或下沉为备查材料；
4. 任何必须依靠超时口头补充才能理解的背景，视为正文缺口。

没有明确时长时，把“答辩形式和规定时长”加入 Open Questions，理解性可以预览，但不能最终
准出。

## Review 输出

先列理解性发现，再给总体判断。每项使用：

```text
[阻塞·陌生评委无法复述 | 背景缺口 | 术语前置 | 时间线堆叠 | 主线埋没 | 贡献模糊 | 价值不明 | 时长不适配] <位置>
评委读到：<原文或章节>
评委会问：<不知道什么或为什么困惑>
缺失认知：<必须先知道的背景、关系、结论或口径>
对判断的影响：<为什么妨碍理解项目或作者贡献>
修复：<补认知坐标、前置结论、解释术语、重组结构、下沉细节或补贡献边界>
```

不得用“表达可以更清晰”代替原文定位和具体认知缺口。

## 准出标准

- 开场定位六问都能仅凭标题和开场摘要回答；
- 六句话复述不依赖外部上下文、不添加原文没有的事实和因果；
- 首次出现的内部概念都有普通语言解释，指代对象唯一；
- 正文按问题结构和认知依赖组织，没有用项目时间线代替结构；
- 评委能区分项目结果、团队贡献和作者个人判断；
- 评委能说明问题为什么难、作者的判断为什么关键，以及业务价值、选型依据和效果证据；
- 产物适配已确认时长；未确认时长时不得最终准出；
- 理解性阻塞发现为零。

任一条件不满足时，`require_points.md` 不得进入 `approved`，`方案.md` 不得进入 `REVIEWED`。
